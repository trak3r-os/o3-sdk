## Safety first

- **Back up the SD card** first, the whole card.
- **The card's state** (verified 2026-10-25 by the test session over track3r-os's USB console): `Firmware/` holds only
  `o3os_1.0.0.ptf`, the track3r-os v1.0.0 release the unit runs. 11 old QA builds were moved, not deleted, into `Firmware-old/`.
- **Install by the card, by the maintainer only, for all four images** (track3r-os `docs/manual/install.md`, section 1): copy the image
  into `Firmware/`, rename the copy `PolyendTracker_0.0.1.ptf` (the reset button was seen flashing only names that start with
  `PolyendTracker`, at most 24 characters), make it the **only** `.ptf` in `Firmware/`, then the hidden reset button. None of the four
  has a USB console (milestone M2b), so track3r-os's USB path (`o3console.py --put` / `--update`) is not used in this session: the card
  is the only route in and out.
- **Before installing H, move `o3os_1.0.0.ptf` out of `Firmware/`** (for example into `Firmware-old/`). Each later image replaces the
  previous one in `Firmware/` the same way (the rule above: the only `.ptf`).
- **The way back** (the same page, "Going back"): every `.ptf` out of `Firmware/`, the image you want back (`o3os_1.0.0.ptf`, or the
  official `PolyendTracker_<version>.ptf`) alone in `Firmware/`, then the hidden reset button. To return to track3r-os, put a copy of
  `o3os_1.0.0.ptf` alone in `Firmware/`, renamed `PolyendTracker_0.0.1.ptf` like the images above (the reset button's naming rule),
  then the reset button. The bootloader is separate from the image; a hung o3sdk image
  does not remove it. Check M2-15 proves this way back from an o3sdk image.
- **The Power button does nothing in these images** (the power-off is milestone M2b): turn the unit off by removing its power.
- **Volume:** headphones off the ears and the amplifier low for the first sound (M2-9, and P-1). The outputs open about a second after
  power-up with one amplifier click; anything louder is a finding.

## The status LED (the only output before the screen)

`PTC19`, active low (`platform/mk66/README.md`, "Faults and blink codes"): steady on right after power-up = the SDRAM tests running;
a 100 ms pulse every second = heartbeat, all well. A code is n flashes then a pause, repeated: 2 clock, 3 SDRAM, 4 no display chip,
5 display on the slow path, 6 (twice, then heartbeat) a crash in the previous run, 8 display stalled, 9 app failed (screen dark),
10 audio bring-up failed, 11 audio fault since boot, 12 a render over 60 % of the block, 13 a key scanner did not answer. Dark = the
image did not start.

## Image F, the FT812 fill-rate test (after H and T; card only, no sound)

Built from `apps/fillrate/README.md`. Its purpose: measure the FT812's per-line limit before o3-303's bitmap skin is built
(`../o3-303/docs/M3B-PLAN.md`, S4). The skin's busiest line asks for 2,034 bitmap and 2,174 filled pixels. Install F as in "Safety
first" (it replaces the previous image in `Firmware/`). Simulator reference: `sim-fillrate/` (`01_k0.png` ... `12_k0_grid_off.png`).
The simulator draws F2 (BILINEAR) with NEAREST; the unit draws BILINEAR. Keys: encoder K (0..32; SHIFT + turn steps 4); F1 L8 NEAREST,
F2 L8 BILINEAR scaled 4/3, F3 L4 NEAREST, F4 filled RECT, F5 MIX, F6 cell width, F7 ballast, F8 K = 0, PLAY the grid on and off.
If the whole picture goes wrong, turn K down; if it does not recover, power-cycle. A chip re-initialisation loses the test bitmaps and
the app does not re-send them: restart the image.
